# 自动报工（MCP）

核心逻辑由 **MCP 服务** 提供，本 skill 只描述工具编排与流程。**不包含任何 Python 代码或 BIP 内部配置。**

> ⚠️ 使用前需已连接 MCP 服务：`streamable http` → `http://<MCP服务器>:51889/mcp`（工具名前缀 `bip_`）。
> ⚠️ 账号密码从对话获取，作为 `username`/`password` 参数**必传**给每个工具（各用户用自己的 BIP 账号，服务器不提供默认凭据）。

## 意图 → 工具映射

| 用户说 | 调用 | 追问条件 |
|---|---|---|
| 只提供凭据 / "扫描" / "查看考勤" | `bip_scan` + `bip_submitted`（串行），汇总为紧凑表格 | 缺凭据 |
| "报工"（凭据就绪） | `bip_preview` → 渲染表格+表单供用户确认 → 按确认提交 | 缺凭据 |
| "报工" + 任务/项目等参数 | `bip_preview` 展示上下文；`bip_report` 提交；任务/项目未指定时用 `bip_list_phases` 列出可选并让用户选，**禁止自动选第一条** | 追问缺失必填参数 |
| "批量报工" / "自动报工" | `bip_preview` 展示待报日期 → `bip_auto_report` | 缺工作类别或内容 |
| "拆分报工" / 描述同日多任务+多工时（自动识别） | 引导用户列出拆分明细 → `bip_split_report` 一次传入 | 缺拆分明细 |
| "查看报工单" | `bip_submitted`（单独执行） | — |
| "查看任务" | `bip_list_phases`（单独执行） | 缺工作类别；项目类缺项目 |
| "删除报工单 RPTxxx" | `bip_delete_doc` | 缺单号 |
| "撤销报工单 RPTxxx" | `bip_revoke_doc` | 缺单号 |

## 报工流程

1. 调 `bip_preview`（只此一次，不要另调 scan/submitted/form_data）→ 汇总成紧凑表格（待报工/已报工/异常/无考勤/报工单概况，某分类为空则省略）
2. 解析 `【表单数据】` JSON，把 `rows`（默认覆盖全部待报日）渲染成表格供用户核对/编辑：`日期 | 工作类别 | 任务/阶段 | 报工内容 | 标准工时 | 加班工时`；工作类别/任务从 `workTypes`/`commonTasks`/`recentProjects`/`projectTasks` 提供候选；正常日工时预填考勤值，异常日留空由用户填；`content` 由用户填写，提交后**原样使用**，禁止润色、缩写
3. 无待报工 → 表格说明全部已报工，不生成表单；有已驳回单 → 提醒"可删除后重新报工"
4. 用户确认后**直接按行提交**，不再重新扫描、不追问：
   - **1 行** → `bip_report(date, work_type, phase_id, content, [project_id], [hours])`
   - **多行（拆分）** → `bip_split_report(date, items)`，每行一个 item：部门工作 `"类别|任务|内容|标准工时|加班工时"`（5段），项目类 `"类别|项目ID|任务|内容|标准工时|加班工时"`（6段）；禁止用 JSON/文件方式传拆分数据
   - `phase_id`/`project_id` 支持名称关键词模糊匹配；匹配失败先 `bip_list_phases` 解析成真实 ID 再提交；字段缺失或工具报错（任务不存在、日期已报工）→ 向用户报告后重调 `bip_preview` 修正，**禁止擅自猜测参数**

## 核心规则

- 凭据就绪后必须先 `bip_preview` 展示分析结果，**分析报告出来前禁止追问日期、工时、任务、内容等参数**
- **绝不替用户猜测参数**：`phase_id`、`project_id`、`content` 必须由用户明确指定，禁止自动选取第一条
- `content` 必须使用用户原话，禁止润色、缩写、改写或补充
- 部门工作 → 无需项目；项目工时/销售支持 → 需项目
- 考勤异常（工时=0）→ 报错，要求用户指定 `hours`（除非已显式指定）；已报工日期 → 禁止重复提交，提示先删除原报工单
- 拆分报工 → 单日多任务用 `bip_split_report` 一次提交，不要逐条独立提交
- 审批通过(8) → 不可删除、不可撤销；已撤销(2) → 无需再次撤销（状态码含义见 `bip_submitted` 工具说明）
- `bip_submitted` 默认返回最近一批（约 20 条），接口不支持翻页；用户质疑"查询不全"时如实说明
